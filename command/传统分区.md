传统分区
===

**fdisk 与 parted**​ 是 Linux 系统中用于**传统磁盘分区（MBR/GPT）**的两大核心命令行工具。它们用于创建、删除、调整分区表，是服务器上线、磁盘扩容和存储规划的基础操作手段。本文档将涵盖 **分区创建、挂载、扩容、缩减**​ 的完整操作流程。

> ⚠️ **高危警告**：磁盘分区操作具有**破坏性**，一旦误操作可能导致数据永久丢失。请在测试环境练习后再在生产环境执行。

* * *

补充说明
----

在 Linux 中，磁盘管理分为三层：

1. **物理磁盘**：`/dev/sdb`, `/dev/nvme0n1`

2. **分区表**：MBR（老，最大 2TB）或 GPT（新，支持大容量）

3. **文件系统**：ext4, xfs 等（格式化后才有文件系统）

**fdisk**：适用于 MBR 和部分 GPT，交互简单，适合小于 2TB 的磁盘。

**parted**：支持 GPT 和大磁盘，适合脚本化和自动化，功能更强。

* * *

语法
--

### fdisk

    fdisk [设备路径]

### parted

    parted [选项] [设备] [命令]

* * *

选项
--

### fdisk 常用选项

| 选项   | 说明        |
| ---- | --------- |
| `-l` | 列出所有磁盘分区表 |
| `-u` | 以扇区为单位显示  |

### parted 常用选项

| 选项   | 说明        |
| ---- | --------- |
| `-l` | 列出所有块设备   |
| `-s` | 脚本模式（不交互） |

* * *

参数
--

| 参数             | 说明                   |
| -------------- | -------------------- |
| `/dev/sdb`     | SCSI/SATA 磁盘         |
| `/dev/nvme0n1` | NVMe SSD             |
| `/dev/vdb`     | 虚拟化磁盘（KVM/OpenStack） |

实例
--

* * *

一、传统分区与挂载操作（以新盘为例）
------------------

### 场景：新增一块 500GB 磁盘 `/dev/sdb`，挂载到 `/data`

### Step 1：查看磁盘

    lsblk
    fdisk -l

### Step 2：分区（MBR 示例）

    fdisk /dev/sdb

交互流程：
    n       # 新建分区
    p       # 主分区
    1       # 分区号
    回车    # 起始扇区默认
    回车    # 结束扇区（全部空间）
    w       # 保存并退出

### Step 3：创建文件系统（格式化）

    mkfs.ext4 /dev/sdb1
    # 或 XFS
    mkfs.xfs /dev/sdb1

### Step 4：挂载

    mkdir /data
    mount /dev/sdb1 /data

### Step 5：开机自动挂载（fstab）

    blkid /dev/sdb1
    # 获取 UUID
    vim /etc/fstab

添加：

```
UUID=xxxx-xxxx /data ext4 defaults 0 2
```

验证

```
mount -a 
df -h
```

* * *

二、GPT 分区操作（推荐）
--------------

### 使用 parted 创建 GPT 分区

    parted /dev/sdb

交互命令：

```
mklabel gpt 
mkpart primary 
ext4 1MiB 100% align-check optimal 1 
quit
```

* * *

三、扩容操作步骤（Ext4）
--------------

> ✅ **前提**：分区后面有连续未分配空间

### Step 1：删除旧分区，保留数据

    fdisk /dev/sdb
    d   # 删除分区
    n   # 新建分区（起始扇区必须完全一致！）
    p   # 查看
    w

### Step 2：重启通知内核

    partprobe /dev/sdb

### Step 3：在线扩容文件系统

    resize2fs /dev/sdb1

* * *

四、缩减操作步骤（高风险）
-------------

> ❌ **不支持 XFS 缩减！仅限 Ext4**

### Step 1：卸载分区

    umount /data

### Step 2：强制检查文件系统

    e2fsck -f /dev/sdb1

### Step 3：缩小文件系统

    resize2fs /dev/sdb1 200G

### Step 4：缩小分区

    parted /dev/sdb
    resizepart 1 200GB

### Step 5：重新挂载

    mount /dev/sdb1 /data

* * *

六、关键注意事项（必读）
------------

### 🚨 数据安全

| 风险点       | 说明                    |
| --------- | --------------------- |
| 起始扇区不一致   | 扩容时起始扇区变化 = **数据全毁**​ |
| XFS 不能缩小  | 误删只能重装                |
| 未备份 fstab | 系统可能无法启动              |
| 直接 rm -rf | 比分区更致命                |

### ✅ 最佳实践

1. **操作前备份**
      dd if=/dev/sdb of=/backup/sdb.mbr bs=512 count=1

2. **使用 UUID 挂载**

3. **生产环境优先 LVM**

4. **GPT 替代 MBR**

5. **测试机验证后再上生产**

* * *

七、故障排查
------

### 1️⃣ 分区看不到？

    partprobe
    reboot

### 2️⃣ 挂载失败？

    dmesg | tail
    journalctl -xe

### 3️⃣ 文件系统损坏？

    fsck -y /dev/sdb1

* * *

八、扩展知识
------

### MBR vs GPT

| 特性   | MBR   | GPT    |
| ---- | ----- | ------ |
| 最大磁盘 | 2TB   | 9.4ZB  |
| 分区数量 | 4 主分区 | 128+   |
| 容错   | 无     | 有备份分区表 |
| 推荐   | ❌     | ✅      |

### 文件系统对比

| 文件系统  | 特点        |
| ----- | --------- |
| ext4  | 稳定、支持缩减   |
| xfs   | 高性能、不支持缩减 |
| btrfs | 快照、压缩     |
