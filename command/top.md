top
===

**top（Table of Processes）**​ 是 Linux / Unix 系统中最核心、最经典的**实时动态进程监控工具**。它能够实时显示系统的整体负载情况（CPU、内存、交换分区）以及各个进程的资源消耗详情，是系统管理员进行性能分析、故障排查和进程管理的首选工具。
补充说明

----

**top 命令**​ 提供了一个动态的、交互式的实时视图。它不同于 `ps`（静态快照），top 会持续刷新屏幕，展示此刻正在发生的事情。

top 的界面通常分为两部分：

1. **概要区（Summary Area）**：屏幕顶部，显示系统时间、运行时间、负载、任务数、CPU 百分比、内存使用情况等。

2. **任务区（Task Area）**：屏幕主体，以表格形式列出所有进程及其资源占用详情。

> 💡 **替代者**：在现代 Linux 发行版中，`top`往往被功能更强的 `htop`或 `btop`取代，但 `top`是所有发行版默认预装的，掌握它是基本功。

* * *

### 语法

    top [选项]

* * *

### 选项

| 选项          | 说明                                            |
| ----------- | --------------------------------------------- |
| `-d <秒>`    | 设置刷新间隔时间（秒）。例如 `-d 5`每 5 秒刷新一次。               |
| `-n <次数>`   | 指定刷新次数后退出。例如 `-n 3`刷新 3 次后自动关闭。               |
| `-p <PID>`  | **监控指定 PID 的进程**（逗号分隔）。例如 `-p 1234,5678`。     |
| `-u <用户名>`  | 仅显示指定用户的进程。                                   |
| `-b`        | **批处理模式（Batch Mode）**。通常用于重定向到文件或管道，不会接受键盘输入。 |
| `-c`        | 启动时显示完整的命令行路径（Command 列）。                     |
| `-H`        | 显示线程（Threads）而非进程。                            |
| `-o <字段>`   | 启动时按指定字段排序（如 `-o %CPU`）。                      |
| `-w [cols]` | 设置输出宽度（防止截断长命令）。                              |

* * *

### 参数

top 命令本身没有位置参数，主要通过 **交互式命令**（运行时按键）来控制。

* * *

### 实例

#### 1️⃣ 基础监控

    # 启动 top
    top

#### 2️⃣ 指定刷新频率

    # 每 2 秒刷新一次
    top -d 2

#### 3️⃣ 监控特定进程

    # 监控 PID 为 1 (systemd) 和 PID 为 1234 的进程
    top -p 1,1234

#### 4️⃣ 监控特定用户

    # 只显示 root 用户的进程
    top -u root

#### 5️⃣ 批处理模式（用于脚本或保存日志）

    # 刷新 10 次，每次间隔 1 秒，输出到文件
    top -b -n 10 -d 1 > top_snapshot.log

* * *

### 详细操作指南（交互式命令）

在 top 运行时，按下以下键位可以改变显示方式或管理进程。

#### 📌 全局控制

| 按键               | 功能                     |
| ---------------- | ---------------------- |
| `q`              | **退出 top**。            |
| `h`或 `?`         | 显示帮助画面。                |
| `Enter`/ `Space` | 立即刷新。                  |
| `d`或 `s`         | 更改刷新延迟时间（默认为 3 秒）。     |
| `B`              | 切换高亮显示（Running 进程会加粗）。 |

#### 📌 显示布局切换

| 按键          | 功能                                             |
| ----------- | ---------------------------------------------- |
| `l`         | 切换显示 **系统负载（Load Average）**​ 行。                |
| `t`         | 切换 **CPU 状态**​ 行的显示方式（条形图/摘要）。                 |
| `m`         | 切换 **内存（Memory）**​ 行的显示方式。                     |
| `1`         | **展开/折叠 CPU 核心**。在多核系统中，按 `1`可以看到每个 core 的使用率。 |
| `u`         | 仅显示指定用户的进程（提示输入用户名）。                           |
| `Shift + u` | 取消用户过滤。                                        |

#### 📌 排序（最重要）

| 按键  | 功能                     |
| --- | ---------------------- |
| `P` | 按 **CPU 使用率**​ 排序（默认）。 |
| `M` | 按 **内存（RES）使用率**​ 排序。  |
| `T` | 按 **运行时间（TIME+）**​ 排序。 |
| `N` | 按 **PID**​ 排序。         |
| `R` | **反转**​ 当前排序顺序。        |

#### 📌 颜色与高亮

| 按键  | 功能                    |
| --- | --------------------- |
| `z` | 切换单色/彩色模式。            |
| `x` | 高亮显示 **排序列**。         |
| `y` | 高亮显示 **正在运行的进程**。     |
| `b` | 开启/关闭粗体显示（配合 x/y 使用）。 |

#### 📌 进程管理（信号发送）

| 按键  | 功能                                             |
| --- | ---------------------------------------------- |
| `k` | **杀死进程**。提示输入 PID，然后输入信号量（默认 15）。              |
| `r` | **重设优先级（Renice）**。提示输入 PID 和 nice 值（-20 到 19）。 |

#### 📌 字段管理

| 按键  | 功能                                                   |
| --- | ---------------------------------------------------- |
| `f` | 进入 **字段管理**​ 界面。可以开启/关闭显示的列，以及设置排序列。                 |
| `o` | 设置过滤器（类似 `top -o`）。例如输入 `%CPU>10`只显示 CPU 大于 10% 的进程。 |

### 界面详解（读懂每一列）

理解 top 的输出是性能分析的关键。

#### 1. 概要区（Top Lines）

**第 1 行：系统概况**
    top - 14:30:01 up 10 days,  2:15,  2 users,  load average: 0.05, 0.10, 0.15

* `up 10 days`：系统已运行时间。

* `load average`：**系统负载**。三个数值分别代表 1分钟、5分钟、15分钟的平均负载。**核心数等于负载阈值**（单核负载 1.00 满负荷，四核负载 4.00 满负荷）。

**第 2 行：任务（Tasks）**
    Tasks: 120 total,   1 running, 119 sleeping,   0 stopped,   0 zombie

* `running`：正在占用 CPU 的进程。

* `sleeping`：等待事件（如 IO）的进程。

* `zombie`：**僵尸进程**。如果不为 0 且持续增长，说明有程序 Bug。

**第 3 行：CPU 状态**
    %Cpu(s):  1.0 us,  0.5 sy,  0.0 ni, 98.5 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st

* `us`：**用户空间**占用 CPU 百分比（你的应用程序）。

* `sy`：**内核空间**占用 CPU 百分比（系统调用）。

* `id`：**空闲**​ CPU 百分比。

* `wa`：**IO 等待**。如果这个值很高，说明磁盘或网络 IO 是瓶颈。

* `st`：**被偷取的时间**（Steal Time）。在虚拟机中，如果此值高，说明宿主机资源紧张。

**第 4/5 行：内存**
    MiB Mem :   7982.3 total,   1024.0 free,   4096.0 used,   2862.3 buff/cache
    MiB Swap:   2048.0 total,   2048.0 free,      0.0 used.

* `buff/cache`：缓存。**Linux 会尽可能利用空闲内存做缓存**，这部分内存在程序需要时会被回收，不算浪费。

* `Swap`：交换分区。如果 `used`不为 0，说明物理内存不足，系统开始使用硬盘交换，性能会急剧下降。

#### 2. 任务区（Process List）

| 列名        | 含义        | 关键点                                |
| --------- | --------- | ---------------------------------- |
| `PID`     | 进程 ID     | 用于 kill 或 renice                   |
| `USER`    | 进程所有者     |                                    |
| `PR`      | 优先级       | RT 代表实时优先级                         |
| `NI`      | Nice 值    | 负值优先级高，正值低                         |
| `VIRT`    | 虚拟内存      | 进程申请的总内存（包含未分配、swap）               |
| `RES`     | **常驻内存**​ | **实际使用的物理内存**（不包含 swap）。排查内存泄漏看这里。 |
| `SHR`     | 共享内存      | 可能被其他进程共享的内存                       |
| `S`       | 状态        | R=运行, S=睡眠, D=不可中断睡眠, Z=僵尸, T=停止   |
| `%CPU`    | CPU 占比    | 单核最大 100%，4核最大 400%                |
| `%MEM`    | 内存占比      | RES / Total Memory                 |
| `TIME+`   | CPU 时间    | 进程自启动以来占用的 CPU 总时长                 |
| `COMMAND` | 命令名       | `c`键可切换显示完整路径                      |

### 扩展知识

#### 批处理模式（Batch Mode）实战

当你需要通过脚本记录服务器状态，或者在 Docker 容器中查看进程时，`-b`选项非常重要。
    # 记录凌晨 3 点到 4 点的 CPU 情况
    for i in {1..60}; do top -b -n 1 >> top.log; sleep 60; done

#### 结合 grep 使用

由于 top 默认是交互的，不能直接 grep。必须使用 `-b`。
    top -b -n 1 | grep nginx

#### 为什么我的内存看起来满了？

Linux 的设计哲学是 **“空闲内存就是浪费的内存”**。重点关注 `available`列（如果 top 版本支持）或观察 `Swap`是否开始使用，而不是 `free`列。

### 注意

* **不要随意 `kill -9`**：在 top 中使用 `k`命令时，默认信号是 15（SIGTERM，优雅终止）。除非进程无响应，否则尽量不要直接发 9（SIGKILL），这可能导致数据丢失或资源未释放。

* **top 消耗资源**：虽然 top 很轻量，但在极其繁忙的系统（如上下文切换极高的系统）中，频繁运行 top 可能会轻微增加负载。

* **容器环境**：在 Docker 或 Kubernetes 容器中运行 `top`，通常看到的是宿主机的资源情况（取决于 cgroup 挂载情况），除非容器开启了特权模式或特定的资源视图隔离。

* **别名问题**：有些系统会给 top 设置别名（alias），例如 `alias top='top -c'`。如果发现 top 行为和预期不同，检查 `type top`。
