top
===

显示或管理执行中的程序

* ✅ 哪些状态是**正常**

* ⚠️ 哪些状态是**异常**

* 🧠 如何通过参数判断系统是否健康 

一、top 命令简介
----------

`top`是 Linux 下最常用的**实时系统监控工具**，用于查看：

* CPU 使用情况

* 内存使用情况

* 进程运行状态

* 系统负载情况

在 CentOS 7 中，`top`默认来自 `procps-ng`包。

* * *

二、基本使用方法
--------

### 1️⃣ 启动 top

    top

进入交互式界面，默认 **3 秒刷新一次**。

* * *

### 2️⃣ 常用交互命令（必须掌握）

| 按键  | 作用              |
| --- | --------------- |
| `q` | 退出 top          |
| `h` | 帮助              |
| `1` | 显示所有 CPU 核心     |
| `P` | 按 CPU 排序        |
| `M` | 按内存排序           |
| `T` | 按运行时间排序         |
| `k` | 终止进程（输入 PID）    |
| `r` | 调整进程优先级（renice） |
| `z` | 彩色显示            |
| `c` | 显示完整命令          |
| `u` | 只看某个用户          |
| `d` | 修改刷新间隔          |

* * *

三、top 输出结构详解（重点）
----------------

### 第一部分：系统整体信息（前 5 行）

#### 第 1 行：系统运行概况

    top - 10:30:45 up 45 days,  3:12,  2 users,  load average: 0.15, 0.25, 0.30

| 字段             | 含义    | 正常       | 异常       |
| -------------- | ----- | -------- | -------- |
| `up 45 days`   | 运行时长  | 越长越好     | 频繁重启     |
| `2 users`      | 登录用户数 | ≤ 正常运维人数 | 不明用户     |
| `load average` | 系统负载  | < CPU 核数 | > CPU 核数 |

✅ **判断标准**：
    load average < CPU 核心数 → 正常
    load average > CPU 核心数 → 繁忙

示例：

* 4 核 CPU：`load > 4`❌ 异常

* * *

#### 第 2 行：任务统计

    Tasks: 120 total,   1 running, 119 sleeping,   0 stopped,   0 zombie

| 状态       | 正常  | 异常   |
| -------- | --- | ---- |
| running  | 少量  | 持续大量 |
| sleeping | 正常  | —    |
| stopped  | 0   | >0   |
| zombie   | 0   | >0 ❌ |

⚠️ **僵尸进程（zombie）必须排查**

* * *

#### 第 3 行：CPU 使用率

    %Cpu(s):  2.3 us,  1.2 sy,  0.0 ni, 96.0 id,  0.3 wa,  0.0 hi,  0.2 si

| 指标   | 含义      | 正常    | 异常     |
| ---- | ------- | ----- | ------ |
| `us` | 用户态 CPU | < 70% | >80%   |
| `sy` | 内核态 CPU | < 20% | >30%   |
| `id` | 空闲 CPU  | > 20% | <10% ❌ |
| `wa` | IO 等待   | < 5%  | >10% ❌ |
| `si` | 软中断     | < 5%  | >10%   |

✅ **判断口诀**：

> CPU 不是看用了多少，而是看 **id 是否太小、wa 是否太大**

* * *

#### 第 4 行：内存（物理内存）

    KiB Mem :  8000000 total,  1000000 free,  5000000 used,  2000000 buff/cache

| 字段         | 正常    | 异常      |
| ---------- | ----- | ------- |
| free       | 有一定剩余 | 接近 0    |
| used       | 可接受   | 持续增长不释放 |
| buff/cache | 正常    | —       |

⚠️ **Linux 会主动使用内存做缓存，不代表内存不够**

* * *

#### 第 5 行：Swap 使用

    KiB Swap:  4000000 total,  3900000 free,   100000 used

| 指标        | 正常    | 异常     |
| --------- | ----- | ------ |
| used swap | 0 或很小 | 持续增长 ❌ |

✅ **Swap 被频繁使用 = 内存不足**

* * *

四、进程列表字段详解（下半部分）
----------------

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND

| 字段      | 含义        | 关注点           |
| ------- | --------- | ------------- |
| PID     | 进程 ID     | kill / strace |
| USER    | 所属用户      | 是否异常用户        |
| PR      | 优先级       | 越小越优先         |
| NI      | nice 值    | -20 ~ 19      |
| VIRT    | 虚拟内存      | 参考            |
| RES     | 实际内存      | ✅重点           |
| SHR     | 共享内存      | —             |
| S       | 状态        | R / S / D / Z |
| %CPU    | CPU 占用    | 单进程 >300% 异常  |
| %MEM    | 内存占比      | >50% 警惕       |
| TIME+   | 累计 CPU 时间 | —             |
| COMMAND | 启动命令      | 是否可疑          |

* * *

### 进程状态（S 列）

| 状态  | 含义     | 是否正常       |
| --- | ------ | ---------- |
| R   | 运行中    | ✅          |
| S   | 睡眠     | ✅          |
| D   | 不可中断睡眠 | ⚠️（常见于 IO） |
| Z   | 僵尸进程   | ❌          |
| T   | 停止     | ⚠️         |

* * *

五、异常判断速查表（重点）
-------------

### ✅ 正常系统特征

* load average < CPU 核数

* CPU idle > 20%

* iowait < 5%

* 无僵尸进程

* swap 几乎未使用

* 单个进程不会长期占满 CPU

* * *

### ❌ 异常信号清单

| 现象                | 可能原因           |
| ----------------- | -------------- |
| load average 持续飙高 | CPU 不够 / IO 瓶颈 |
| wa 很高             | 磁盘慢 / 数据库压力大   |
| 大量 D 状态进程         | IO 阻塞          |
| 僵尸进程              | 程序 bug         |
| swap 持续增长         | 内存泄漏           |
| 某进程 CPU 100% × N  | 死循环 / 计算密集     |
| buff/cache 无法回收   | 内存压力           |

* * *

六、常见排查流程（实战）
------------

### 1️⃣ CPU 高

    top
    P

* 找到 `%CPU`最高的进程

* 查看是否是业务进程

* 结合 `strace`、`perf`

* * *

### 2️⃣ 内存高

    top
    M

* 看 RES 是否异常

* 检查是否 Java / Python / Node 进程

* * *

### 3️⃣ 负载高但 CPU 不高

✅ **典型 IO 问题**

* 看 `wa`

* 用 `iostat -x 1`

* * *

### 4️⃣ 僵尸进程处理

    ps -A -ostat,pid | grep Z
    kill -9 PPID

* * *

七、top 常用组合命令
------------

    top -u nginx        # 指定用户
    top -p 12345        # 指定进程
    top -H -p 12345     # 查看线程

* * *

八、总结一句话版（给你自己看的）
----------------

> top 看的是趋势，不是瞬间值；
> 
> 看 idle、load、wa、swap 和 zombie，比看 CPU 百分比更重要。
